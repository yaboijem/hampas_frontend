# CI design

## Goal

Add GitHub Actions CI to **hampas_frontend** and **hampas_backend** so PRs and `main` fail when lint, tests, or build break.

## Scope

**In**

- One workflow file per repo: `.github/workflows/ci.yml`
- Triggers: `pull_request` and `push` to `main`
- Frontend: `npm ci` → lint → test → build
- Backend: Composer install → Pint `--test` → PHPUnit via `php artisan test`
- Short README note in each repo pointing at CI

**Out**

- Deploy, coverage upload, E2E, dependency bots
- Branch protection UI (manual in GitHub settings)
- Other improvement slices (queue, policies, React Query, auth)

## Approach

Minimal gate (Approach A): match existing local scripts; no secrets; no version matrix.

## Frontend (`hampas_frontend`)

**File:** `.github/workflows/ci.yml` (name only; keep short)

| Step | Detail |
|------|--------|
| Runner | `ubuntu-latest` |
| Node | 24, npm cache via `actions/setup-node` |
| Install | `npm ci` |
| Lint | `npm run lint` |
| Test | `npm test` |
| Build | `npm run build` with `VITE_API_URL=https://api.example.com/api` |

Permissions: `contents: read` only.

## Backend (`hampas_backend`)

**File:** `.github/workflows/ci.yml`

| Step | Detail |
|------|--------|
| Runner | `ubuntu-latest` |
| PHP | 8.4 + common Laravel extensions (mbstring, xml, ctype, curl, zip, sqlite, bcmath, tokenizer) |
| Composer | cache + `composer install --no-interaction --prefer-dist` |
| Key | `php artisan key:generate --force` after copy `.env.example` → `.env` if needed |
| Style | `vendor/bin/pint --test` |
| Test | `php artisan test` (phpunit.xml already uses sqlite `:memory:`) |

No external Postgres/Redis/S3. phpunit.xml testing env is authoritative.

Permissions: `contents: read` only.

## Triggers (both)

```yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
```

## Success criteria

1. Broken test or lint on a PR → red check
2. Local green (`npm test` / `php artisan test`) → CI green when tree matches
3. No required secrets for a green run
4. Filenames stay short: `ci.yml`, `ci-design.md`, plan `ci.md`

## Follow-ups (not this slice)

Queue worker, Policies, TanStack Query, auth cookies, admin reports UI — separate specs.
